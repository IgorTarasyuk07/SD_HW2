# ПОС — преподавательская оценка студентов

ДЗ №2 по КПО (DDD, Ports & Adapters, паттерны GoF). Консольное приложение на C# / .NET 8.

## Запуск

Из папки с `Pos.sln`:

```bash
dotnet build
dotnet run --project Pos.Cli
dotnet run --project Pos.Cli -- --demo
dotnet test
```

В меню можно добавить студента и критерий, посмотреть список студентов и рубрикатор, выставить,
исправить или отменить оценку, посмотреть оценки и итог студента, вывести аналитику по критериям
и выгрузить итоги всех студентов. Студент и критерий выбираются по номеру из соответствующего списка.
Дробные числа можно вводить с точкой или запятой.

Ведомость сохраняется в `gradebook.json` в текущей папке. При экспорте в той же папке создаётся или
обновляется `results.csv` (UTF-8). В CSV есть номер и имя студента, итог из 10, число выставленных
оценок и число критериев. Демо использует свою временную ведомость и сохраняет `demo-results.csv`.
В нём видны выставление оценок, отклонение балла 12 из 10, исправление, отмена, расчёт и экспорт.

## Доменная модель

| Термин | Тип | Роль в модели |
| --- | --- | --- |
| Студент | `Student` | Entity. Студенты различаются по номеру, даже если имена совпадают. |
| Критерий | `Criterion` | Entity внутри рубрикатора. Имеет номер, название, положительный максимум и вес. |
| Оценка | `Evaluation`, `Score` | Оценка связывает студента и критерий. `Score` — неизменяемый Value Object. Два балла с одинаковым значением равны. |
| Ведомость и рубрикатор | `Gradebook` | Корень агрегата. Хранит студентов, критерии и оценки одного курса. |
| Итог | `FinalScoreCalculator`, `FinalScore` | Domain Service рассчитывает итог по текущей ведомости. `FinalScore` содержит результат и число оценённых критериев. |
| Репозиторий ведомости | `IGradebookRepository` | Порт прикладного слоя. Сценарии получают и обновляют агрегат через него. |

Оценка выставляется через `Gradebook.SetEvaluation`. Ведомость ищет студента и критерий по номеру,
а `Evaluation.Create` проверяет диапазон от нуля до максимума критерия включительно. Для пары
«студент — критерий» хранится одна оценка. Повторное выставление заменяет её после проверки нового
балла. Отмена убирает оценку из ведомости. При чтении JSON действуют те же правила, что при вводе.

## Расчёт итога

Для критерия с выставленной оценкой считаем долю от максимума и умножаем её на вес. Затем делим
сумму вкладов на сумму весов **всех** критериев и умножаем на 10. Веса относительные. Значения 3 и 2
означают тот же вклад, что 60 и 40. Например, при оценках 16 из 20 и 9 из 10 получится
`10 × (3 × 16/20 + 2 × 9/10) / (3 + 2) = 8,4`.

Пропущенная или отменённая оценка даёт нулевой вклад. Число оценённых критериев позволяет отличить
пропуск от выставленного нуля. При пустом рубрикаторе итог не определён, в CSV поле остаётся
пустым. Итог пересчитывается при запросе и экспорте. В консоли и CSV он выводится с точностью до
двух знаков после точки. Аналитика по каждому критерию показывает число оценённых студентов и
средний балл среди выставленных оценок.

## Архитектура

Ports & Adapters. Каждый слой оформлен отдельным проектом. Стрелки показывают зависимости в коде.

```text
Pos.Cli ───────► Pos.Application ───────► Pos.Domain
    │                   ▲
    └──► Pos.Adapters ──┘
```

- `Pos.Domain` хранит модель, правила и расчёт итога. У проекта нет зависимостей на другие слои.
- `Pos.Application` содержит сценарии в `PosFacade` и порты `IGradebookRepository`, `IResultExporter`.
- `Pos.Adapters` реализует хранение в JSON и выгрузку в CSV. Форматы файлов обрабатываются здесь.
- `Pos.Cli` отвечает за ввод и вывод. `Program` собирает зависимости в DI-контейнере и передаёт
  управление `ConsoleApp`.

## Паттерны GoF

- **Фабрика (порождающий).** `Evaluation.Create` — единственная точка создания оценки. Она получает
  критерий из ведомости, проверяет оба предела балла и только затем вызывает закрытый конструктор.
  При исправлении оценки и чтении JSON используется тот же путь.
- **Facade (структурный).** `PosFacade` даёт консоли единый интерфейс сценариев. Например, для
  экспорта консоль вызывает один метод, а фасад читает ведомость, считает итоги и отдаёт их
  адаптеру выгрузки.
- **Strategy (поведенческий).** `FinalScoreCalculator` собирает данные студента и передаёт их
  `IFinalScorePolicy`. В DI зарегистрирована `WeightedScorePolicy`. Если изменится формула итога,
  можно заменить эту политику в контейнере. Подмена правила проверяется отдельным тестом.

## Тесты

xUnit-тесты проверяют границы балла, существование студента и критерия, сохранение старой оценки
после некорректной попытки исправления, перерасчёт после замены и отмены и случай пустого рубрикатора.
Отдельный тест проверяет чтение сохранённой ведомости и обновление выгрузки после отмены оценки.
